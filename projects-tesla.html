01

Retrieval-augmented generation

Confluence RAG Chatbot

Confluence APIEmbeddingsOpenSearch vectorsAzure OpenAI (internal)Python
Problem

Onboarding took months. The team's knowledge was scattered across hundreds of Confluence pages, so the fastest search engine was whoever had been around longest.

What I built
  • Ingest: pulled every page through the Confluence API and chunked it into retrievable passages.
  • Index: embedded each chunk and stored the vectors in OpenSearch.
  • Answer: embedded the incoming question, retrieved the closest passages, and grounded generation on them with an internally hosted Azure OpenAI model, so documentation never left the firm's boundary.

02

Compute efficiency

Airflow DAG Cost Optimization

Apache AirflowAWS EC2Parent/child DAGsPython
Problem

A 10-year-old daily pipeline producing profitability reports ran 10.5 hours across 7–8 parent/child DAGs, spinning EC2 instances up and down.

Individual jobs had been edited piecemeal for a decade. Nobody had looked at the compute picture as a whole.

What I built

I treated the pipeline as one system for the first time, mapping every DAG, dependency and instance, then pulled three levers:

  • Shutdown timing: tightened when instances shut down so nodes stop billing once their work is done.
  • Right-sizing: matched instance types to each step's actual workload.
  • Parallelization: ran steps concurrently wherever no real dependency existed between them.

03

Data integrity at scale

4M Cost Center Migration

Apache AirflowPython rule engineDatabricksSHA-2 hashing
Problem

When JPMorgan's Corporate Banking merged into CIB, ~4 million cost centers had to migrate, each with 30 attributes.

Tolerance for data loss or duplication: zero. Comparing every field naively meant 120 million checks.

What I built
  • Orchestration: Airflow-driven batch migration, processed on Databricks.
  • Rules: a Python rule engine encoding 7 layers of business rules.
  • Tier-1 validation: one SHA-2 hash per record collapsed 30 attribute checks into a single value: 4M checks instead of 4M×30.
  • Tier-2 validation: summed hashes across batches of ~25,000 records. Only a batch whose sums disagreed got opened record by record.
