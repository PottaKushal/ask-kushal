Production pipeline

Airflow Pipeline Optimization

Apache AirflowAWS EC2Python
Problem

A ~10-year-old daily pipeline producing profitability reports ran 10.5 hours, spinning EC2 instances up and down.

Jobs had been edited piecemeal for years. Nobody had looked at the compute picture as a whole.

What I built

I was asked to optimize one job. I treated the whole pipeline as one system instead, traced its EC2 utilization, and fixed three root causes:

  • Tighter shutdown timing so instances stop once their work is done.
  • Right-sized instances matched to each step.
  • Parallel execution for steps that never depended on each other.

Data accuracy at scale

4M Cost-Center Migration

SHA-2 hashingPythonApache AirflowDatabricks
Problem

When JPMorgan's Corporate Banking merged into CIB, 4M+ cost centers had to migrate, each with 30 attributes, with zero tolerance for data loss or duplication.

The migration ran as Airflow-orchestrated batches with a Python rule engine, processed on Databricks. Comparing every field naively meant 120M checks.

What I built

I designed and implemented the validation layer: a two-tier hash comparison.

  • Tier 1: one SHA-2 hash per record turns 30 attribute checks into a single value per record.
  • Tier 2: hashes summed across batches of ~25,000 records. Only a batch whose sums disagree gets opened record by record.

Problem

Onboarding took months: team knowledge was scattered across hundreds of Confluence pages.

What I built

Pulled pages via the Confluence API, chunked and embedded them into OpenSearch, and generated answers with internally hosted Azure OpenAI.

Impact

Natural-language questions surface the relevant passages instantly, instead of new joiners asking the same people the same questions.
